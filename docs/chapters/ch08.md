# Chapter 8: DefectDojo

Goal: every scan report is uploaded to DefectDojo, so findings live in one place with history.

## Steps

1. Server (size F2as v6, 8 GiB): add an 8 GB swap file, then check Docker and Compose:

        sudo fallocate -l 8G /swapfile
        sudo chmod 600 /swapfile
        sudo mkswap /swapfile
        sudo swapon /swapfile
        echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
        free -h

2. Clone the official repository and check out the newest stable tag (tags have no "v": use the grep, the plain sort lists old v1.x tags first):

        cd ~
        git clone https://github.com/DefectDojo/django-DefectDojo.git
        cd django-DefectDojo
        git tag --sort=-v:refname | grep -E '^[0-9]' | head -8
        git checkout 3.4.304

3. Add our override (localhost only). Do not run docker/setEnv.sh: it replaces docker-compose.override.yml.

        cat > docker-compose.override.yml <<'EOT'
        services:
          nginx:
            ports: !override
              - "127.0.0.1:8080:8080"
        EOT
        docker compose config --services

4. Start it (the first start downloads the images) and check:

        docker compose up -d
        docker compose ps
        docker compose logs initializer | grep "Admin password:"

5. From your PC open a tunnel (leave it running) and log in at http://localhost:8080 as admin:

        ssh -N -L 8080:127.0.0.1:8080 -i "$env:USERPROFILE\.ssh\devsecops-lab" azureuser@VM_PUBLIC_IP

6. In DefectDojo take the API v2 Key. In GitHub add the secret DOJO_API_KEY and the variables
   DOJO_URL = http://127.0.0.1:8080 and DOJO_ENABLED = true.
7. Copy the stage file over the pipeline, commit and push:

        Copy-Item stages\pipeline-ch08.yml .github\workflows\pipeline.yml
        git add .github\workflows\pipeline.yml stages\pipeline-ch08.yml
        git commit -m "ch08: upload scan reports to DefectDojo"
        git push

8. Tag and push: git tag ch08, git push --tags. Stop the VM (deallocate).

## What the pipeline does

- New step "Upload reports to DefectDojo" (only when DOJO_ENABLED is true) runs scripts/dojo_import.py.
- It re-imports the three reports into product "OWASP Juice Shop", engagement "branch: NAME", one test per scanner. A second run
  updates the same findings; findings missing from a new report are closed.
- The step sits before the gate (enforce), so a blocked run still delivers its findings.

## Notes

- Result for Juice Shop v20.3.0: 86 active findings (43 Semgrep, 43 Trivy), 0 Gitleaks. The main run is red because of the gate.
- The pipeline reaches DefectDojo on 127.0.0.1 because the runner is on the same server.
- Release 3.4.304 uses images from registry.defectdojo.com. The "Assets" menu is where products are listed.
- Memory: 7.7 GiB plus 8 GB swap was enough for DefectDojo alone. Chapter 9 adds Kafka and Mattermost, so the server is resized to F4as v6.
- Never put the API key on screen or in a file.

## Done when

DefectDojo shows the Juice Shop findings, and the run page shows the upload step green.
