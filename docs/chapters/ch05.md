# Chapter 5: Code scanning with Semgrep

Goal: the pipeline scans the source of a real app (OWASP Juice Shop) and every finding has an address.

## Steps

1. Start the VM; the runner shows Idle. Check the app version exists:

        git ls-remote --tags https://github.com/juice-shop/juice-shop v20.3.0

2. Copy the stage file over the pipeline, commit and push:

        Copy-Item stages\pipeline-ch05.yml .github\workflows\pipeline.yml
        git add .github\workflows\pipeline.yml stages\pipeline-ch05.yml
        git commit -m "ch05: add Semgrep code scanning to the pipeline"
        git push

3. Actions, pipeline run: the summary shows Gitleaks (no secrets) and Semgrep (43 findings:
   13 ERROR, 28 WARNING, 2 MEDIUM) with the top rules.
4. Improvement made in this chapter: a second table "Top ERROR findings (file and line)" on the run summary.
   Committed as "ch05: show file and line for the top Semgrep findings".
5. Follow one finding: express-sequelize-injection in routes/login.ts line 34 (the query is built from
   req.body.email and the password). Open it on GitHub at the scanned tag:
   https://github.com/juice-shop/juice-shop/blob/v20.3.0/routes/login.ts#L34
6. Tag and push: git tag ch05, git push --tags. Stop the VM (deallocate).

## What the pipeline does

- Checks out Juice Shop (tag from the repo variable JUICE_SHOP_TAG, default v20.3.0) into the folder app.
- Runs Semgrep in a container with p/javascript, p/typescript and p/owasp-top-ten, metrics off,
  JSON report reports/semgrep.json.
- Prints counts by severity, the top rules and the top ERROR findings (file and line) on the run summary page.
- Report only: the job stays green. The gate comes in chapter 7.

## Notes

- Some findings are in the app's own CI files and in training files (codefixes), not in the app logic.
  A finding is a lead, not a verdict: is it real, reachable, how bad?
- The fix for the login finding is a parameterized query (input kept apart from the command).
- Never expose Juice Shop to the internet.

## Done when

The run summary lists the Semgrep findings with file and line, and routes/login.ts line 34 is shown.
