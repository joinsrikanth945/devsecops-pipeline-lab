# Chapter 4: Secret scanning with Gitleaks

Goal: the pipeline scans the repository and its whole history for secrets on every push.

## Steps

1. Start the VM and check Settings, Actions, Runners: the runner shows Idle.
2. Copy the stage file into the workflows folder, commit and push:

        Copy-Item stages\pipeline-ch04.yml .github\workflows\pipeline.yml
        git add .github\workflows\pipeline.yml stages\pipeline-ch04.yml
        git commit -m "ch04: add the pipeline with Gitleaks secret scanning"
        git push

3. Actions, pipeline: the run is green and the summary says "No secrets found".
4. Demo on a throw-away branch with a FAKE token (ghp_ plus 36 random characters, made up
   on the spot). Commit it, delete it, commit again, push the branch.
5. Actions, pipeline, Run workflow, branch demo-leak: the summary lists 1 possible secret
   (rule github-pat, file demo/settings.env, line 1, the commit that added it). The value is redacted.
6. Clean up: switch to main, delete the demo branch on GitHub and locally.
7. Tag and push: git tag ch04, git push --tags. Stop the VM (deallocate).

## What the pipeline does

- Runs on the self-hosted runner, checks out the full history (fetch-depth 0).
- Runs Gitleaks v8.30.1 in a container, with --redact and --exit-code 0 (report only).
- Writes reports/gitleaks.json, uploads it as an artifact (14 days) and prints a findings
  table on the run summary page (added in this chapter).

## Notes

- The job is green even when a secret is found: this chapter only reports. Chapter 7 adds the gate.
- If a real secret leaks: revoke it first, treat it as exposed forever, keep the scan.
- Never plant test secrets on main, never use a real key.

## Done when

The clean run says no secrets, and the demo-leak run reports github-pat in demo/settings.env.
